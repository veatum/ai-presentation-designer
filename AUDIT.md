# AUDIT — v7.4.2

## 1. Назначение

Аудит является частью pipeline и выполняется после сохранения PPTX. Он проверяет физический результат файла, а не только внутренний семантический план.

ТЗ допускает расширение или сокращение набора ориентиров из Appendix 1 при явном обосновании. Поэтому раздел ниже показывает, что проверяет текущая реализация и что сознательно осталось ручным/неполным.

## 3. Семантические проверки

`core/quality.py` и LLM stages проверяют:

- соответствие утверждений исходным материалам;
- source/claim relationships;
- числовые утверждения;
- content density;
- финальную fact review;
- библиографию;
- отсутствие некоторых служебных/контентных ошибок.

Эти проверки могут быть недетерминированными и поэтому не заменяют физический audit.

## 4. User-selected repair

Пользователь видит audit findings и может выбрать одно или несколько замечаний.

API:

```text
POST /api/repair/{run_id}
```

Поле:

```text
selected_issues=<JSON array>
```

Сервис:

1. валидирует JSON;
2. отбрасывает некорректные записи;
3. дедуплицирует одинаковые findings;
4. ограничивает payload;
5. отправляет только выбранные findings в targeted repair;
6. повторно рендерит и проводит audit.

Пустой список отклоняется. Таким образом, repair не является обязательным «исправить всё».

## 5. Тестовое покрытие

Для релиза v7.4.2 существует **55 собранных test cases**.

Основные тестовые области:

- targeted audit findings;
- targeted repair route;
- text-to-image adapter и fallback;
- image reliability;
- regression suite;
- web resilience;
- pipeline/schema/source checks;
- native PPTX payload preservation;
- built-in templates;
- unknown-template rendering;
- export routes;
- validation/timeout behavior.

Запуск:

```bash
python scripts/final_test_suite.py
```

## 6. Appendix 1: что не автоматизируется полностью

Сознательно не заявляется как полностью автоматическая проверка:

- полный SmartArt audit;
- CV-level detection любых сложных визуальных коллизий;
- экспертная оценка любого логотипа/колонтитула в произвольном сложном master;
- полная browser compatibility matrix.

Это ограничения области автоматического QA, а не скрытые утверждения о полном соответствии всех возможных слайдов.

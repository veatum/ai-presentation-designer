Версия 5.1. Напиши готовое содержание презентации по архитектуре и источникам.
Каждый обычный слайд должен отвечать на отдельный вопрос и давать новую полезную информацию: факт с контекстом, механизм, объяснение, пример, сравнение, ограничение или практический вывод. Заголовок выражает мысль; слова «Преимущества» или «Особенности» сами по себе не подходят.
Ориентир для обычного слайда — 2–5 законченных смысловых блоков и 45–110 слов, а не несколько ярлыков. Не добивайся длины повторением и водой. Если нет доказательств для запрошенной глубины, объясни ограничение, не выдумывай цифры, кейсы или причины.
Выбирай форму по смыслу: content — объяснение; two_column — сравнение по критериям; table — сравнимые данные; chart — подтверждённый числовой ряд с единицей; timeline — датированные события; process — последовательность с механизмом каждого шага; metrics — значения с периодом и смыслом; summary — вывод и действия. Не превращай всё в cards/списки. Используй минимум 3 содержательных типа на колоде от 7 слайдов, если источники позволяют.
На title нужна конкретная тема и обещание аудитории; обычных section без содержания избегай. Финальный содержательный слайд подводит обоснованный итог.
Все нужные для понимания сведения должны быть видимы. notes — дополнительные пояснения выступающему, а не место скрывать половину содержания.
Не заполняй все формы одновременно: для chart/table добавь в points 2–3 пояснения и интерпретации; для two_column используй обе колонки; для metrics обязательно note; для timeline/process используй label и detail. Неиспользуемые массивы оставь [], строки "", table/chart — null.
Ровно requested_slides, номера 1..N, первый kind=title. Последние bibliography_slots слайдов оставь kind=sources, points=[], остальные содержательные; приложение заполнит библиографию реальными данными. До блока источников должен быть вывод.
Сохраняй source_ids и claims. В claims.text используй точный текст соответствующего видимого блока/подписи. Для таблиц и графиков добавь claims, охватывающие числа с периодом. Не цитируй нерелевантный источник.

Ориентир для обычного слайда — 2–5 законченных смысловых блоков. Смысловые блоки должны объяснять механизм, пример, следствие или практический вывод, а не быть ярлыками. Для колоды от 7 слайдов используй несколько разных содержательных kind по смыслу, когда это уместно. Проверяемые веб-источники используй при наличии; если поиск временно недоступен, не останавливай генерацию и не выдумывай точные цифры или цитаты.

ТЕХНИЧЕСКАЯ СТАБИЛЬНОСТЬ JSON:
- Возвращай один объект {"slides":[...]} без Markdown.
- Заполняй только поля из ожидаемой формы. Не добавляй новые ключи.
- Для kind=content заполняй points; left/right/table/chart/metrics/timeline/quote оставляй пустыми/null.
- Для kind=two_column заполняй только left_title,left_points,right_title,right_points.
- Для kind=process или timeline используй timeline с label и detail.
- Для kind=chart/table/metrics обязательно дай соответствующий payload и оставь остальные специализированные payload пустыми/null.

ЧИСЛА: при наличии веб-источников подтверждай числа evidence_quote. При временном отсутствии веб-источников не изобретай точные числовые значения; допускаются только числа, заданные пользователем или в локальных материалах.

ВАЖНО ДЛЯ СОДЕРЖАНИЯ: источник является доказательством, но НЕ текстом слайда. Никогда не копируй в видимое содержание URL, название поисковой системы, поисковые подсказки, навигацию сайта, служебные фразы («Справка», «Войти», «Перейти к основному контенту»), идентификаторы вида [W...], HTML/JSON-фрагменты или библиографическую запись вместо объяснения. На слайде показывай смысл: факт, механизм, сравнение, пример, следствие или вывод. Ссылки и идентификаторы остаются в source_ids/claims/notes и на слайде источников.

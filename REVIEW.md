# Финальный технический разбор — v7.4.2-final

Этот файл фиксирует состояние текущего релиза перед публикацией. Он не заменяет нормативное ТЗ: требования кейса и границы реализации сверяются с `TЗ_COVERAGE.md`.

## Что исправлено в финальной подготовке

| Область | Состояние v7.4.2-final |
|---|---|
| Выборочное исправление аудита | Пользователь отмечает конкретные проблемы чекбоксами; backend принимает только выбранные findings. Кнопки «исправить всё» нет. |
| Аудит верстки | Добавлены/расширены bounds, overflow, overlap, placeholder, duplicate, occupancy и часть token/contrast/density проверок. |
| Контентный аудит | Сохранены проверки источников, чисел, смыслового соответствия и наличия содержимого; AI-проверки явно отделены от детерминированных. |
| Изображения | Есть два режима: retrieval (Openverse/Wikimedia) и опциональный text-to-image через Hugging Face Inference Providers. Для старта без HF token используется retrieval fallback. |
| Три варианта | Встроены `balanced`, `columns`, `editorial`; добавлен showcase одного контента в трёх вариантах и матрица 3×3 для трёх шаблонов. |
| Неизвестный шаблон | Пользовательский PPTX проходит через тот же parser/renderer pipeline; отдельный acceptance-сценарий оставлен в `scripts/acceptance_run.py`. |
| Документация | README, ARCHITECTURE, MODELS, AUDIT, TЗ_COVERAGE и checklist приведены к одной версии. |
| Docker | Есть `Dockerfile`, `docker-compose.yml`, `.env.example`; Docker опционален, основной локальный запуск — без контейнера. |
| Секреты | Действующий API key не хранится в архиве; `.env` исключён через `.gitignore`/`.dockerignore`. |

## Что проверки доказывают

Детерминированные тесты проверяют структуру JSON, сохранность payload в PPTX, нативные таблицы/диаграммы, экспорт, bounds/overflow и часть контентных ограничений. Тесты выборочного repair отдельно проверяют, что backend получает только выбранные проблемы.

Semantic/LLM проверки не являются математическим доказательством истинности текста. `verified` для веб-источника означает успешную загрузку/разбор источника, а не независимую экспертную проверку каждого утверждения.

## Известные ограничения

- Полное воспроизведение произвольных сложных SmartArt, фирменных иллюстраций и нестандартных композиций не гарантируется.
- Для точной типографики шрифт шаблона должен быть доступен в окружении; предусмотрен переносимый fallback.
- Набор audit-проверок расширен, но не утверждает исчерпывающее покрытие каждого возможного визуального дефекта из Appendix 1.
- Retrieval изображений и text-to-image — разные режимы. Retrieval не выдаётся за text-to-image.
- Text-to-image является опциональным: требуется HF token/доступ к выбранному провайдеру. Без него приложение использует retrieval fallback.
- Для Top-10 команд требование обязательного VK inference является внешним организационным условием и не может быть заменено локальным VPS.
- Полноценный browser matrix должен быть подтверждён на финальной машине команды; автоматические серверные тесты не заменяют проверку всех браузеров на macOS/Windows.
- Ограничение времени генерации зависит от внешнего API, сети и сложности задачи; в проекте установлен бюджет около пяти минут и предусмотрен явный отказ при исчерпании времени.
- Локальный режим не имеет пользовательской авторизации. Не публикуйте его в интернет без отдельного слоя доступа/защиты.

## Что нужно выполнить непосредственно перед отправкой

1. Опубликовать репозиторий с открытым доступом.
2. Сделать финальный Git tag, соответствующий `VERSION`.
3. Запустить clean-run тестов; Docker проверять только если команда выбирает этот дополнительный путь.
4. Открыть репозиторий в режиме инкогнито и проверить отсутствие авторизации.
5. Проверить три showcase-варианта одной колоды и 3×3 матрицу примеров.
